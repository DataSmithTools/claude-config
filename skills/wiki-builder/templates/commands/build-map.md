Build/refresh maps of content for: $ARGUMENTS (default: wherever notes cluster). If the
wiki-builder skill is available, follow its references/maps.md; otherwise:

1. Read INDEX.md, then only the notes in the target area.
2. MOC when 5+ concept notes share a theme (04-maps-of-content): 2-3 sentence orientation,
   links in deliberate reading order with half-line hooks, a Frontier section for gaps.
   Max depth: INDEX -> MOC -> notes. Split MOCs past ~30 links.
3. GLOSSARY.md: one opinionated definition per project-specific term
   (`**Term**: def` + `_Avoid_: aliases`); no dictionary padding.
4. If the mission is learning: a pathway note - ordered stages of existing notes, prerequisites
   first, each stage with "what you can do after"; point gaps at 05-questions.
5. Fix trivial duplicates/orphans on sight; file bigger ones as question notes for /review-vault.
6. Update INDEX.md (group concepts under MOC headings), append LOG.md line, report what changed.
